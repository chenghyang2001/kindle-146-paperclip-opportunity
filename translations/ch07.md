# 第 7 章　Hermes 與 OpenClaw 當員工（Hermes and OpenClaw as Employees）

> 所屬區塊：BLOCK 2・ORGANIZE（組織）
> 本章副題：客戶既有的代理能不能擔任某個角色？要怎麼查證？

## 本章核心問題

「我自己的 Hermes 代理，能坐進那張 org chart（組織圖）嗎？」

作者的綜合案例：一位經營小型顧問公司的客戶，已經用 Hermes Agent 處理個人工作好幾個月，它保管她的研究筆記、替她起草提案，她信任它就像信任一位好助理。顧問展示了一家替她公司做每週報告的 Paperclip 公司之後，她問出了決定案子能否成交的問題：「我的 Hermes 能坐進那張組織圖嗎？還是我得從頭換一套？」

顧問第一個直覺是說「可以」——她在文件裡看過內建的 Hermes adapter（適配器），答案感覺很確定。接著她想起客戶第二台機器上可能還跑著一個 OpenClaw，而且她在某處看過「OpenClaw adapter 即將推出」。她停了下來：這個問題的答案不在她的記憶裡，而在一頁文件上——那頁在她讀的那天是真的，到安裝那天不一定還是。

於是她只說自己有把握的話：在確定範圍前，她會查目前的 adapter 狀態，把查到的東西標上日期，並把公司設計成「查證結果允許時，客戶偏好的代理就能坐上那個位子」。客戶說，這是第一次有廠商用「一套流程」而不是「一個承諾」來回答相容性問題。

## 7.1 自帶代理：adapter 怎麼運作

adapter 是 Paperclip 和實際做事的 runtime 之間的連接；它的商業意義是：客戶偏好的代理可以去填公司裡的一個角色。

回想貫穿全書的分工：**Paperclip 是 control plane（控制層）**，掌管組織圖、goal chain（目標鏈）、預算、核准和紀錄；**runtime** 是把模型變成「能接任務、會用工具、交得出產出」的員工的軟體；adapter 夾在兩者之間。代理在 heartbeat（心跳）醒來時，adapter 啟動或聯繫 runtime、把任務和指令交給它、收回結果，並把結果、用量和 session state（階段狀態）回報給控制層。10 月 20 日閱讀的文件說，這正是 Paperclip 能接上非它自己打造的代理的原因：它管的是代理怎麼一起工作，而不是代理本身是什麼。

這個分工有直接的商業價值。第 2 章遇到的客戶多半已經在用好幾個 AI 工具；第 5 章設計角色時，刻意不先決定由誰來填。adapter 讓角色由客戶已經信任的代理來填。一個得放棄自己喜歡的工具才能採用你設計的客戶，可能會拒絕；一個能保留偏好 runtime、又得到周邊結構的客戶，會答應。**選 runtime 是在角色定義之後才做的人事決定，不要讓可用的 runtime 反過來決定角色。**

### 內建 adapter 狀態表（2026 年 10 月 20 日文件）

| Runtime | 文件中的狀態標籤 | 備註 |
| --- | --- | --- |
| Claude Code | Selectable（推薦） | 本機命令列代理 |
| Codex | Selectable（推薦） | 本機命令列代理 |
| 其他命令列代理（Cursor、OpenCode、Pi、Grok、Kimi Code 等） | Selectable | 本機命令列代理 |
| Hermes Agent | Selectable | 內建，見 7.2 |
| Paperclip 自己的 native runner | Experimental | 依實例設定 |
| OpenClaw gateway | Coming soon（請用 OpenClaw 邀請流程） | 見 7.3 |
| Process（shell 指令、腳本） | Coming soon（只能經 API 或匯入） | 不在介面下拉選單 |
| HTTP（webhook 式呼叫） | Coming soon（只能經 API 或匯入） | 不在介面下拉選單 |
| ACPX Local、Hermes Gateway | Retired | 只剩導覽標籤 |

要像謹慎的客戶讀合約那樣讀這張表：

- **Selectable**：今天就能在介面裡選。
- **Experimental**：專案還在測試，不要在沒說明的情況下拿它當客戶案的基礎。
- **Coming soon**：這項能力還不是介面裡的正常選項，不管背後還有什麼可能是真的。
- **Retired**：已經沒了。

本書的原則、也是你在每次客戶會議都該守的原則：**coming soon 的能力永遠不描述成可用。** 你可以說文件寫了什麼（附日期），可以說你會驗證什麼，但不能說它能用。

還有一個顧問該知道、但不該粉飾的細節：同一份文件也說，OpenClaw gateway、shell process、webhook 這三個 adapter 在執行時是完整可用的，只是還不能在介面手動選，必須透過程式介面或匯入的公司設定來配置。「coming soon」的標籤和「執行時可用」的說明可能出現在同一頁。兩者都要講，照頁面的順序講，讓客戶看到你沒有挑方便的那一句。

### 不是內建的 runtime：三條路

文件描述了三種方式：

1. **OpenClaw 邀請流程**：外部代理透過 onboarding prompt 加入，申請送來給人核准。
2. **webhook**：Paperclip 送喚醒訊息給客戶營運的服務，由那個服務做事並更新任務。
3. **自寫腳本**：用計時器輪詢工作，Paperclip 端完全沒有 adapter。

指南推薦前兩種用在正式環境；第三種最簡單也最受限：沒有排程或留言觸發的喚醒、沒有自動成本追蹤，腳本自己就是自己的 heartbeat。

### 成本回報決定預算上限有沒有用

最後那個限制對第 3 區塊的一切都有影響。**Paperclip 的預算是依照「有紀錄的花費」來強制執行的**；成本沒回報給控制層的代理，預算就看不見它。設計採用非標準 runtime 的公司時，要及早問：這個 adapter 每次執行後會不會回報 token 用量和成本？如果不會，第 8 章設的上限保護不了這個角色，你需要別的控制手段，例如在模型供應商那端設限額，並寫進 Blueprint（藍圖）。**沒有成本回報的 runtime，就是一個沒有天花板的角色。**

### 另外兩個會影響「開箱可信度」的事實

- 文件說 Claude Code、Codex、OpenCode、Gemini CLI 的 coding adapter 預設為 full-auto mode（全自動），代理執行工具不會先詢問核准，包括來自已連接服務的工具。值得原文轉告客戶的意思是：全自動講的是「核准提示」，不是「代理在公司裡被允許做什麼」；公司的權限、預算和核准規則仍然適用。
- 每個 adapter 都需要自己的憑證，存在某個地方；金鑰遺失的角色，就是會停擺的角色。

**多數人的做法**：因為在文件某處看過這個 runtime 的名字，就告訴客戶「可以，支援你的代理」。
**有效的做法**：說「我在｛日期｝讀的文件把你的 runtime 列為｛狀態標籤｝。確定建置範圍前我會再查一次，在一家乾淨的公司上跑一次測試，並確認它會回報成本。會的話它就坐上那個位子；不會的話，我們在供應商那端加一道限額。」

重點：adapter 是一個人事決定，有三件事要驗證——狀態標籤、是否回報成本、預設會做什麼。

## 7.2 內建的 Hermes adapter

Hermes adapter 讓客戶的 Hermes Agent 擔任 Paperclip 公司裡的角色；依賴它之前要做的功課，是驗證它的需求、成本回報，以及它被允許自己做什麼。

**Hermes 是什麼。** Hermes Agent 是 Nous Research 推出的開源代理，MIT 授權，跑在你自己控制的基礎設施上。它的特色是 learning loop（學習循環）：保有整理過的記憶、從完成的任務建立可重用的 skill 並持續改進，內建大量工具，也能以連接訊息平台的程序執行。一句話：一個會記得、會進步、客戶可能早就信任的能幹單一代理。

**這兩項特質讓它在 Paperclip 公司裡是強員工。** 持久記憶讓代理能帶著上下文接續工作；自建的 skill 讓它在重複任務上越做越好，不必你重寫指令。一個已經調到符合客戶寫作風格的 Hermes，不需要重新調校。進到公司裡，它得到獨自一個代理時缺少的東西：角色、目標鏈、主管、天花板和閘門。

**adapter 本身（10 月 20 日文件）：**

- 內建並隨 Paperclip 一起出貨，不用裝外掛，沒有 experimental 或 retired 標籤。
- **需要 Hermes Agent 和 Paperclip 裝在同一台機器上**，並有較新版本的 Python。
- 一次跑一個任務：每次執行處理一個查詢就結束；開啟 session persistence（階段延續）時，每次執行會接續前一個 session，所以對話上下文、記憶和工具狀態可以跨次延續。
- 介面裡合併兩種 skill 來源：Paperclip 管理的 skill（董事會可以開關），以及 Hermes 原生的 skill（對董事會唯讀、永遠載入）。
- adapter 從 Hermes 的輸出讀出 token 用量、session 識別碼和成本，每次執行後回報給 Paperclip。

**承諾任何事之前，逐項推演：**

1. **同機需求。** 客戶的 Hermes 若在另一台機器上，就不能照文件描述使用這個 adapter，答案從「可以」變成「要看情況」。確定範圍前先查清楚他們的 Hermes 跑在哪裡。
2. **模型選擇。** 文件說這個 adapter 沒有模型欄位：Hermes 透過自己的設定管理模型。你的 Blueprint 可能要求某個角色用某個模型，但 Paperclip 不會替你設定。這讓客戶的 Hermes 設定成了你成本控制的一部分，因為模型決定花費——第 8 章會說，模型選擇是成本的兩大驅動因素之一。
3. **工具集。** 一個什麼工具都開著、能碰終端機、檔案和網路的 Hermes，以員工身分運作時，就是一個觸角很廣的工作者，正好是第 6 章最小權限姿態的反面。把工具集縮到角色需要的，就像縮 connector 一樣。這是你在這個 adapter 上最有用的一項設定。
4. **skill。** Hermes 原生 skill 對董事會唯讀、永遠載入，而且 Hermes 會自己建立和精修 skill。第 6 章的 skill 版本管理和 skill policy 管得到 Paperclip 管理的 skill，管不到 Hermes 自己學到的東西。學習型代理的行為會在執行之間改變：客戶說週報語氣變了，可能看到的是 Hermes 改寫的 skill。這既是優點也是稽核問題。寫進 Blueprint，並判斷這個角色是否更適合由「行為完全可控」的代理擔任。
5. **成本回報。** adapter 從 Hermes 的輸出解析成本，這表示它依賴輸出格式在 Hermes 各版本間保持不變。要實測：第一次執行後打開 run record（執行紀錄），確認有成本、而且數字合理。如果什麼都沒顯示，在修好之前把這個角色當成「沒有回報」。

### 範本：Hermes adapter 使用前檢查

「1. 客戶的 Hermes 跑在哪？和 Paperclip 同一台：｛是／否｝。2. 安裝的 Hermes 版本：｛版本｝；Python 版本：｛版本｝。3. Hermes 用哪個模型、誰能改：｛答案｝。4. 開啟的工具集：｛清單｝；已縮到角色需要的：｛是／否｝。5. session persistence：｛開／關｝；已確認第二次執行接得上第一次：｛是／否｝。6. 測試任務後 run record 有成本：｛是／否｝。7. 現有的 Hermes 原生 skill：｛清單｝；已審查：｛是／否｝。8. 於｛日期｝讀到的 adapter 狀態標籤：｛標籤｝。」

最常見的錯誤：因為 adapter 是內建的，就停在第 1 項，直到第一張帳單才發現成本從來沒回報。

重點：「內建」代表連線存在，上面的檢查才決定這個角色能不能安全地派人。下一個 runtime 帶著更需要小心的標籤，而讀懂那個標籤的紀律，正是重點。

## 7.3 OpenClaw 與 gateway adapter

OpenClaw 今天就能透過有文件記載的邀請流程加入 Paperclip 公司，但它的 gateway adapter 標示為 coming soon；原則是照實報告這個差別，一分也不多說。

**OpenClaw 是什麼。** 一個開源、自架、透過訊息應用程式工作的個人 AI 代理，MIT 授權、由獨立非營利基金會管理，gateway 是它的本地控制層。repo 的兩個提醒值得轉告客戶：傳入的訊息是不受信任的輸入；沒設沙箱時工具直接在主機上執行。當天約有三十九萬顆星。

**兩種說法同時成立。** Paperclip 文件把 OpenClaw gateway adapter 標為「coming soon」，旁邊的備註說要用 OpenClaw 邀請流程；adapter 總覽頁又說這個 adapter 執行時可用、但還不能在介面選，必須透過程式介面或公司匯出設定來配置。這兩句話從兩個角度描述同一個 adapter。你可以對客戶說的，正是它們共同支持的部分：截至那天，OpenClaw gateway adapter 在介面上標示 coming soon，把 OpenClaw 帶進公司的有文件路線是邀請流程。你不能說的是：gateway adapter 已經可用。

### 邀請流程四步（依自帶代理指南）

1. 你請公司邀請一個外部代理，系統產生一段 onboarding prompt（入職提示）。只有具邀請權限的董事會使用者，以及公司的 CEO 代理能建立邀請。
2. 你把那段提示貼進 OpenClaw 的聊天，代理回呼 Paperclip、送出加入申請。
3. 申請以 hire approval（雇用核准）的形式抵達，和第 4 章的提案一模一樣，由你核准。Paperclip 啟用這個代理並發出一把一次性金鑰。第一次執行時可能需要在 OpenClaw 那端核准 device pairing（裝置配對），出現「pairing required」訊息就表示那一步在等待。
4. 冒煙測試：指派一個瑣碎的 issue，看完執行逐字稿，再把真正的工作交給它。

**讀出這個流程在教什麼。** 雇用核准就是第 4 章遇過的閘門，代表由「人」決定外部代理能不能加入。同樣的習慣適用：核准前打開完整申請讀完。那把一次性金鑰是憑證，所以要寫進登記表，附負責人和審核日期。

**指南列出的限制，要帶進任何範圍討論：**

- 連線靠 OpenClaw 和 Paperclip 之間的持久連結維持；Paperclip 停機時連線中斷，工作暫停到重新連上。
- 指南提到「替 OpenClaw 代理同步 skill」的但書而沒有細述，雇用核准指南則把 skill sync 列為這類代理不支援，所以它們的 skill 是在 OpenClaw runtime 裡管理的。把這解讀為：第 6 章的公司 skill 庫可能送不到 OpenClaw 代理，承諾之前先查證。

**資安要直說。** 擁有 OpenClaw 的客戶，常常讓一個長期運行的代理握著真正的憑證。本章讀到的第三方報導把公開暴露的實例、有風險的社群 skill、prompt injection（提示注入）列為主要威脅。用你對待任何廠商說法的同樣懷疑去衡量那些報導——發布者和這個產品是競爭關係。合理的回應不取決於誰對：把代理跑在隔離的機器或帳號上、把它的 gateway 綁在本機、在它碰到的每個服務都給獨立帳號、維持在最窄可用的權限、把它載入的每個 skill 都當第三方程式碼。這些是第 6 章的做法，第 10 章會補完。**由握有廣泛持久憑證的代理擔任的角色，應該最後才派人。**

### 範本：給客戶的 adapter 狀態說明

「｛日期｝我讀了官方 adapter 文件。｛Runtime｝標示為｛標籤｝。有文件記載的接法是｛路線｝。我已在自己的測試公司驗證｛已測項目｝，尚未驗證｛未測項目｝。建置開始前我會再查一次，有任何變動都會告訴你。」

最常見的錯誤：省略日期——那會把一句真實的陳述，變成一個會過期的承諾。

重點：標籤的精確度，就是你在這裡賣的產品。能說出「這是文件記載的、這是標示 coming soon 的、這是我測過的」的顧問很少見，而被過度承諾的 demo 燒過的客戶聽得出差別。不過，有一種客戶以上都不適用，你能為他做的最有用的事，就是直說。

## 7.4 什麼時候單一代理才是更好的答案

有些客戶不需要一家公司，而說出來，是贏得轉介最可靠的方式。

一家公司有固定開銷：要有人設計角色、設定天花板、審核核准、維護相依項目、追蹤 release notes。當涉及好幾個代理、好幾個人或真金白銀時，這筆開銷值得付；對用量小、單一、個人的客戶，開銷可能超過效益。告訴這種客戶實話不是損失，而是你在會議裡能做的最可信的一件事。

**辨識訊號：** 客戶只有一個職能，由同一個人執行，他同時是審查者也是擁有者；只有一個代理，或一個代理幾乎包辦一切；花費低而可預測；沒有別人需要看代理做了什麼，也沒有別人需要核准。客戶的問題是「能力」，不是「問責」：他要的是更好的助理，不是受管理的團隊。開場那位 Hermes 使用者，可能正是這樣的客戶——對她的個人工作而言是，對公司週報而言則不一定。決定前先把兩種用途分開。

### 作者的試算（明列假設，把監督時間算進去）

- 單人客戶用一個代理，每月 8 個任務，每個省 30 分鐘，時薪 50 美元：毛價值 4 小時，即 200 美元。
- 扣掉假設的每月模型花費 30 美元，以及每個任務 5 分鐘的審查，約 0.67 小時、33 美元：單一代理的淨值約每月 137 美元。
- 加上公司層：假設每月 3 小時的維護（看 release、審登記表、調天花板），即 150 美元。淨值掉到約每月負 13 美元。**公司層的成本比它管理的工作還高。**
- 改變輸入，答案就變：每月 40 個任務時毛價值是 1,000 美元，同樣的開銷只占一小部分。

這套算術不是贊成或反對公司的判決，它顯示的是：損益兩平點取決於量，以及有多少人分攤工作；你應該和客戶在會議中、用他們自己的數字算一次。這裡的假設都是示意，請換掉。

### 範本：單一代理的回答

「依你今天的做法，一個人每月｛數量｝個任務，單一代理比較適合。加一家受管理的公司每月大約要｛時數｝小時維護，在你目前的量下回收不了成本。我寧可現在就告訴你。以下是會改變我答案的事：｛觸發條件｝。只要其中一件發生，打給我，我們再算一次。」

最常見的錯誤：說「你不需要這個」卻沒有給重新評估的觸發條件，留給客戶的是一扇關上的門，而不是一段關係。

重點：公司是管理多個代理、多個人或真金白銀的工具；推薦任何比問題更大的東西，是客戶終究會察覺的判斷失誤。

## 本章小結

- adapter 讓客戶已經信任的代理填進角色：Paperclip 管組織圖、預算、核准和紀錄，runtime 做事；選 runtime 是角色定好後的人事決定。
- 狀態標籤像合約：Selectable 才能說可選，Experimental 要說明在測試，Coming soon 永遠不說成可用，Retired 就是沒了；每句話都附日期。
- 預算依紀錄的花費執行；不回報成本的 runtime 沒有天花板，要靠供應商端限額並寫進 Blueprint。
- Hermes adapter 內建但有條件：同機、模型由 Hermes 管、工具集要縮、原生 skill 唯讀且會自我改寫、成本要實測。
- OpenClaw 今天走四步邀請流程，人核准、一次性金鑰進登記表；gateway adapter 仍是 coming soon，skill sync 不支援，長期憑證的角色最後才派人。
- 全自動模式只關掉工具層的核准提示，公司的權限、預算和核准規則照樣有效。
- 單一代理有時才是誠實的答案：在小量下，公司層比它管理的工作還貴；給出重新評估的觸發條件，留下一段關係。

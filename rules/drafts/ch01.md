# K146 第 1 章規則候選（從員工到公司）

> 來源：《The Paperclip Opportunity》前言、導論、第 1 章。草稿，待彙整與使用者核准。

### 規則 1：每個代理的花費要能歸屬到單一任務

**規則**：不讓多個代理或多項工作共用同一個無法拆帳的帳號，每筆模型花費都要能對回「哪個代理、哪個任務、哪個目標」。

**為什麼**：前言的記帳事務所與 1.1 節的行銷公司都卡在同一點——帳單上 1,180 美元知道是哪家廠商，卻說不出是哪個工具、哪個客戶花的；代理共用帳號，費用與任務對不起來（前言、1.1 Spend）。

**怎麼套用**：多代理工廠（lhf）每個單位執行時，把 `claude -p` 呼叫次數、耗時、單位 ID 寫進同一份 run log；VPS 上的 cron 任務各自記錄呼叫次數。月底要問「這週哪個工作最花額度」時，不必去翻四個地方的 log。

### 規則 2：說法先分三堆，再決定能不能寫進提案或回報

**規則**：引用任何 AI 工具的能力前，先把說法標成「文件記載（可自己驗證）／宣傳／未證實」，只有第一類可以當事實寫出。

**為什麼**：1.3 節把零人力公司的口號、獨立評測與官方功能並排檢驗，要求把「品質不審就能上線」「每月花多少」這類未證實說法排除在提案之外。

**怎麼套用**：Claude 回報研究或比價結果時，對工具功能加註來源類型；使用者準備 AMR／ROS 2 面試作品集時，「已實測」「書上說」「官方宣稱」分開寫，不把演練模擬結果寫成生產環境成果。

### 規則 3：月費與執行成本，試點量測前不報數字

**規則**：在用真實模型與真實排程跑過一段試點之前，不向任何人承諾代理系統的月執行成本，只給量測方法與上下限假設。

**為什麼**：1.3 節指出成本幾乎完全取決於「用哪個模型」與「心跳多久一次」，同一份評測的估計彼此對不上；任一變數改變，月費就倍數變動。

**怎麼套用**：設計 VPS 排程或 NotebookLM 批次時，先跑一輪記錄實際呼叫次數再估月用量；本章演練第 3 步顯示最貴與最便宜組合差 4,320 倍，報價前一律附「試點量測值」欄位。

### 規則 4：核准閘門擋權限，品質檢查要另外設計

**規則**：不要把「有核准閘門、有活動紀錄」當成品質保證；凡是會送到外部的產出，另設一道內容檢查（人審或客觀驗證）。

**為什麼**：1.3 節引用的實測發現代理會寫出沒來源的統計、未檢查就標完成；結論是治理層擋得住權限問題，擋不住錯誤答案，紀錄只說發生了什麼、不說好不好。

**怎麼套用**：寄信、發文、留言、git push 前，除了「使用者同意送出」，還要有驗證代理在乾淨 context 看規格＋產出；工廠的「撰寫→客觀驗證→QA→審查」退回鏈就是這條規則的實作，不可因為有核准就省略驗證。

### 規則 5：先講系統停在哪裡，再講它能做什麼

**規則**：介紹任何自動化或代理方案時，在對方問之前主動說出它不負責的層（模型錯誤、工具權限、伺服器維護、最終品質）以及由誰負責。

**為什麼**：1.4 節的六層堆疊與 1.5 節兩位提案者的對比——先說限制的人預先化解了「出錯怎麼辦」這個讓會議破局的反對意見；堆疊圖是範圍聲明，範圍在出事時保護你。

**怎麼套用**：面試介紹多代理工廠或拍五專案時，先畫出「我負責的層／仰賴的外部層（模型、ROS 2、硬體）」；交付工具給使用者時，回報裡明列「沒處理的風險」與「誰該維護」，例如 VPS 服務由誰備份。

### 規則 6：價值試算一律扣掉人審時間

**規則**：計算代理省下的價值時，用「省下工時價值 − 模型與主機費 − 人審與維護工時」，不只算毛價值。

**為什麼**：1.5 節範例 6,600 − 600 − 1,100 = 4,900 美元；省略 1,100 美元審稿時間的 6,000 美元版本，會被客戶的試算表一天內抓到，之後所有說法都變可疑。

**怎麼套用**：評估要不要把某項例行工作交給代理（例：Kindle pipeline、週報）時，把使用者每次要檢查的分鐘數算進去；若人審時間接近原本手做時間，就不值得自動化。

# K146 第 2 章規則候選：三種會成交的對話

來源：《The Paperclip Opportunity》第 2 章（Visibility／Control／Capacity 三種對話、四個異議）。

### 規則 1：先問對方心裡的問題，再決定要展示什麼

**規則**：介紹任何 AI 代理系統（含自己的多代理工廠）之前，先用一個問題找出對方的痛點類型（看不見／怕失控／想省時），再只展示對應的那一段。

**為什麼**：第 2 章開場兩位顧問的對比——完整導覽組織圖、目標鏈、心跳、預算、核准的人沒成交；只問「AI 工具昨晚花了四百美元你怎麼知道」的人成交了。2.1 也指出 Visibility 對話最常見錯誤是變成技術導覽。

**怎麼套用**：使用者在面試（AMR／ROS 2 工程師）或對外展示長時程多代理工廠、K 書演練成果時，Claude 準備講稿要先列「對方最可能的痛點」與一句開場問題，示範只挑一條主線（例如只展示一個任務從結果追溯到目標），不要整套功能巡禮。

### 規則 2：把對方的恐懼改寫成一條可驗證的控制規格

**規則**：使用者或客戶說出一句擔憂（怕花太多、怕亂寄、怕刪資料）時，立刻把它改寫成「上限／閘門／紀錄」其中一種具體控制，並示範它真的會停下來。

**為什麼**：2.2 的 reframe——「我不能接受無上限的帳單」就是 budget ceiling，「沒經過我不准寄給客戶」就是 approval gate；示範的力量在於系統「會停」。

**怎麼套用**：使用者常說「不要亂扣 API 費用」「信只存草稿」「不要寄出去」，Claude 不只口頭答應，而是落成可檢查的設定：例如 claude -p 走 Max 訂閱並移除 API 金鑰、Gmail 只呼叫 create_draft、工廠的每單位預算上限與等待核准狀態，並在回報中附上「這個控制停下來的證據」。

### 規則 3：講控制時，同一句話說出它攔不住什麼

**規則**：回報任何安全或品質措施時，必須同時列出「它不檢查什麼」，不可只說「已經安全」。

**為什麼**：2.2 最常見錯誤是承諾系統給不了的保護——預算只限花費、核准只閘決策，兩者都不檢查輸出正確性；2.4 回答「這安全嗎」要給「會設定什麼／不會承諾什麼」短清單。

**怎麼套用**：Claude 回報 VPS 服務、NotebookLM 批次、工廠驗收時，用兩欄格式：「已控制：預算、核准、紀錄」＋「未涵蓋：輸出正確性、外部連線風險、備份」；面試作品集描述也照此口徑，避免被追問時失分。

### 規則 4：價值試算一律扣掉人工審查時間，系統成本標「假設」

**規則**：估算 AI 代理能省多少時間或錢時，必須扣除人工審查的時數，並把模型／主機成本明確標成假設，等試行（pilot）實測後才改成實際值。

**為什麼**：2.3 的示意算式 40 份 × 1.5 小時 × 50 美元＝3,000 美元，扣 350（假設）與 667（每份審 20 分鐘）後約 1,983 美元，只剩標題數字的三分之二，但這才是能在客戶試算表活下來的數字。

**怎麼套用**：使用者評估「把每週 Kindle pipeline／YouTube 摘要交給代理省多少時間」、或 VPS 搬遷到 Managed Agents 的成本時，Claude 的表格一定有「審查時間」一欄與「假設／實測」標記；面試時講自動化成果也用扣掉審查後的淨值。

### 規則 5：第一個自動化職能挑「好審、錯了不痛」的那件

**規則**：要把一件重複工作交給代理時，先挑交付物清楚、回饋迴圈短、早期出錯代價低的職能（內部摘要、草稿），對外或不可逆的工作放到之後。

**為什麼**：2.3 Capacity 對話最常見錯誤是選錯職能——客戶最在乎的工作往往最難審、出錯最傷；先在小職能成功，才贏得第二個更大的職能。

**怎麼套用**：使用者想把新工作交給工廠或排程代理時（例如求職信、104 應徵、對外留言），Claude 建議先從內部版（產出草稿到 repo、寄給自己）跑一輪並量審查分鐘數，確認品質後才開啟對外動作，且對外動作保留使用者明確同意。

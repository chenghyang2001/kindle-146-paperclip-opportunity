# K146 第 6 章規則候選：技能、連接器與記憶

### 規則 1：skill 描述寫「何時載入」，不寫「主題」

**規則**：每個 skill 的 description 一律照四段寫——何時用、何時不用、產出什麼、缺輸入時怎麼做。

**為什麼**：代理每次心跳只看名稱和描述，對上才載入本文；描述寫成主題，會在錯的時間載入或永遠不載入（第 6.1 節「Skill description (routing line)」範本與常見錯誤）。

**怎麼套用**：使用者的 `~/.claude/skills/*/SKILL.md` 已有「觸發／不觸發」寫法，新增或修改 skill 時再補兩段：「產出」與「缺輸入時的處置」（例如 NotebookLM skill 缺 notebook id 時要停下來回報，不猜）。多代理工廠的單位規格也照此四段寫。

### 規則 2：缺資料的處置要明寫成「不估計、標記、升級」

**規則**：任何會產出數字、日期、引用的指令或 skill，都要寫明「缺少時寫 not found 並升級給人，不准估計」。

**為什麼**：沒有規則處理缺口的代理會自己即興，即興正是捏造統計數字的來源（第 6.1 節「What makes a good skill」）。

**怎麼套用**：求職作品集、面試答案庫、比價報告、Kindle 摘要裡的數字，子代理找不到來源時一律標「未取得」；派子代理的交接單在「限制」欄固定加這一句。驗證代理把「出現推測數字」列為 FAIL 條件。

### 規則 3：連接器與憑證照「步驟表」授權，不照目錄授權

**規則**：替代理開任何外部存取前，先寫一張「步驟｜服務｜動作｜授權給哪個代理｜登入帳號｜是否先給人審」的表，表上沒有的一律不接。

**為什麼**：目錄有多少個不重要，授出去多少才決定風險；組織層級授權等於讓現在和未來的代理都拿到同樣範圍；以擁有者身分登入，代理就能做擁有者能做的一切（第 6.2 節）。

**怎麼套用**：VPS 上的 bot、n8n、Gmail／Drive 憑證、claude -p 無頭代理的 `--tools` 白名單都照此表盤點；能開專用帳號或專用 token 的就不要用本人主帳號。工廠新增工具權限時，在單位規格寫出這張表。

### 規則 4：跨心跳要延續的東西寫進檔案，並檢查有沒有存到

**規則**：代理（含子代理、claude -p、長時程工廠單位）需要延續的狀態，一律寫進指定檔案；指令中的「照往常／跟上次一樣」改成指向該檔案的路徑。

**為什麼**：代理在心跳之間不保留記憶；最後完成的同步會覆蓋、超過容量的變更會被丟掉，成功的任務不代表檔案存好了，要看同步回條（第 6.3 節）。

**怎麼套用**：supervisor-board.md、HANDOFF、PROGRESS.md 就是 notes file；每次子代理結束要回報「寫入了哪個檔、寫入後的行數或 hash」，主管才標完成。多台 PC 同時寫同一檔時先 pull 再寫，避免「最後同步獲勝」蓋掉別台的進度。

### 規則 5：維護一張帶審核日期的相依性登記表，release notes 一出就對表

**規則**：每個專案對外依賴的服務、套件、模型、憑證與主機都列進登記表（負責人、會壞什麼、上次檢查、下次審核、備案），有官方 release notes 或變更公告時，先用表上每個名字搜尋一遍。

**為什麼**：最貴的失敗不是設計錯，而是沒人盯的相依；broker 退役對有登記表的顧問只是一個排好的下午（第 6.4 節）。

**怎麼套用**：NotebookLM 改名與 CLI 升版、n8n Cloud workspace 消失、Claude Code 預設 full auto 等事件都屬此類；在各專案（VPS、kindle pipeline、lh-factory）放一份 `dependencies.md`，每季或每次升級時花 30 分鐘對表；未驗證的項目照列、審核日排近一點。

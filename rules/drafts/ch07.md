# K146 第 7 章規則候選：Hermes 與 OpenClaw 當員工

### 規則 1：對外講工具能力一律「附日期＋官方標籤＋是否親測」

**規則**：向客戶、面試官或任何外部對象說某個工具／功能「支援、能用」時，一律附上閱讀官方文件的日期、原文狀態標籤，以及自己是否實測過。

**為什麼**：Coming soon 永遠不說成可用；省略日期會把一句真實陳述變成會過期的承諾；被過度承諾燒過的客戶聽得出差別（第 7.1、7.3 節「Adapter status statement」範本）。

**怎麼套用**：求職作品集與面試回答（AMR／ROS 2、Claude Code、Managed Agents）寫成「2026-11 讀官方文件為 GA／Beta，我在 HP1 實測過 X」；Claude 替使用者寫對外文件或回信時，凡提到第三方功能狀態都要查證並標日期，查不到就寫「未驗證」。

### 規則 2：沒有成本回報的執行路徑，要在供應商端另設上限並寫下來

**規則**：任何花錢但不會把用量回報給管控層的代理或腳本，啟用前先在供應商端設限額，並在專案說明寫明「此路徑靠供應商限額控管」。

**為什麼**：Paperclip 的預算依紀錄花費執行，看不見的花費擋不住；沒有成本回報的 runtime 就是沒有天花板的角色（第 7.1 節）。

**怎麼套用**：使用者的 API 盤點（VPS line-gmail-bot、拍五 intent_proto.py、GitHub PR 代理）屬於「Max 訂閱看不到的花費」；每一處在 console.anthropic.com 或對應供應商設月上限，並記在 api-usage-audit 文件；新增自寫輪詢腳本時同樣處理。

### 規則 3：接上既有代理前跑完整份「使用前檢查」，不准停在第一項

**規則**：把任何既有代理或 runtime 接進多代理系統前，逐項確認：跑在哪台機器、版本、用哪個模型誰能改、工具集是否縮到角色需要、session 能否延續、測試後是否看得到成本、自帶 skill 是否審過、狀態標籤與日期。

**為什麼**：最常見的錯誤是看到「內建」就停在第 1 項，直到第一張帳單才發現成本沒回報；學習型代理會自己改寫 skill，行為在執行之間改變（第 7.2 節「Hermes adapter pre-use check」）。

**怎麼套用**：長時程工廠換 runtime、VPS 上的 Hermes／OpenClaw 類代理、跨機器（HP1／HP2／i5）交辦 claude -p 時，用這份八項清單當交接單附件；驗證代理以「八項都有證據」為 PASS 條件。

### 規則 4：全自動只代表工具層不問，對外與不可逆動作仍要人核准

**規則**：即使代理以 full-auto／bypass 權限執行，對外發送、刪除他人資料、付款、git push 到共用分支等動作，仍要保留公司層（人）的核准閘門。

**為什麼**：全自動講的是核准提示，不是代理在公司裡被允許做什麼；公司權限、預算與核准規則仍然適用（第 7.1 節、7.3 節邀請流程的雇用核准）。

**怎麼套用**：使用者在 bypass 模式下跑子代理時，「寄信給別人、104 送出應徵、刪雲端檔」仍照全域規則先取得明確同意；外部代理（OpenClaw 類）加入時，核准前讀完完整申請，一次性金鑰列入登記表。

### 規則 5：規模不到就誠實建議「單一代理」，並給重算觸發條件

**規則**：評估是否要為某件事建多代理系統或管理層時，先把監督與維護時間算進去；算出來不划算就直說，並附上「什麼情況發生就重算」的觸發清單。

**為什麼**：公司有固定開銷；每月 8 個任務時，單一代理淨 137 美元、加公司層變負 13 美元；說「你不需要」卻沒有觸發條件，留下的是關上的門（第 7.4 節「The single-agent answer」）。

**怎麼套用**：使用者想為小任務開長時程工廠、多代理或 VPS 常駐服務時，Claude 先估「每月次數 × 省下時間」與「維護時數」，不划算就建議用單一 claude -p 或 skill，並寫出觸發條件（例如次數超過門檻、需要第二人審、出現意外帳單）。

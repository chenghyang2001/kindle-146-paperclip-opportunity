來源：《The Paperclip Opportunity》（K146）Ch2／Ch4／Ch14／Ch16

本檔收錄「怎麼向別人介紹與展示代理系統」的規則：先找出對方心裡的問題再決定展示什麼，把擔憂轉成看得見的控制，展示只走一條主線並包含系統停下來的畫面；自我介紹與追蹤信有固定結構，不適合的請求早說不並給替代方案。適用於面試、作品集、104 推薦信、追蹤信、對家人朋友或客戶的說明。

## 7 條規則

### B146-56：先問對方心裡的問題，再決定要展示什麼

介紹任何代理系統之前，先用一個問題找出對方的痛點類型（看不見花費與工作／怕失控／想省時），再只展示對應的那一段。
**Why：** 整套功能巡禮會讓對方找不到跟自己有關的部分，反而提出更多疑慮。
**How to apply：** 準備面試或對外展示工廠、K 書演練成果時，講稿先列「對方最可能的痛點」與一句開場問題，只挑一條主線。
來源：Ch2 規則 1

### B146-57：把對方的恐懼改寫成可驗證的控制規格，並示範它會停

使用者或對方說出一句擔憂（怕花太多、怕亂寄、怕刪資料）時，立刻改寫成「上限／閘門／紀錄」其中一種具體控制，並示範它真的會停下來。
**Why：** 口頭保證無法化解擔憂，看得見的停止證據才行。
**How to apply：** 使用者說「不要亂扣 API 費用」「信只存草稿」時，落成可檢查的設定：claude -p 走 Max 訂閱並移除 API 金鑰、Gmail 只呼叫 create_draft、工廠的每單位預算與等待核准狀態，並在回報附「這個控制停下來的證據」。
來源：Ch2 規則 2

### B146-58：展示只秀一個完成任務追到目標，並包含它停下來的樣子

對外展示代理系統時，依序只給：組織圖、一個完成的任務（交辦＋產出）、往上追溯到目標、乾淨的紀錄，再排進一段「預算或關卡把它擋下來」的畫面，並在對方問之前說出它不做什麼；最後停下來問對方最想接哪個工具。
**Why：** 展示停下來的樣子，比展示它能做多少更能建立信任。
**How to apply：** 面試展示 lh-factory 時依「組織圖 → 目標鏈 → 一個完成單位的紀錄 → 驗證失敗被退回 → 核准閘門 → 一個做不到的事」排列，附實測失敗率；準備「任務 → 產出 → 目標」單頁，並坦白說哪一次失敗、為什麼。
來源：Ch4 規則 5、Ch14 規則 1

### B146-59：靠即時狀態觸發的展示，先彩排並備錄影

要現場觸發才看得到的效果（預算到頂暫停、看門狗砍程序、Gazebo 撞牆停車），展示前至少彩排兩次，並準備一段成功版錄影，用的時候直說是錄影。
**Why：** 即時狀態最容易在現場失靈，沒備案時整段展示會變成除錯。
**How to apply：** 面試 demo、K 系列演練錄影、NotebookLM 展示的準備清單列「彩排紀錄＋備案錄影檔路徑」；拍五或 WSL Gazebo 現場 demo 前先在螢幕 3 錄一段成功版存進對應 repo。
來源：Ch14 規則 2

### B146-60：一句話介紹要有「對象＋問題＋界線」，禁用誇大字

寫自我介紹、作品集首句、104 推薦信開頭或服務簡介時，用「我幫誰回答什麼問題、怎麼做、我不承諾什麼」的結構，十秒內念完；不出現「轉型」「顛覆」「全自動」「睡覺時幫你經營」這類字。
**Why：** 誇大字讓有經驗的人立刻打折扣；說出界線反而顯得可信。
**How to apply：** 寫 104 自我推薦信或面試自介第一句時，先產出三段式的一句，再列出它的界線（例：「我沒有量產 AMR 車隊經驗，但有完整 Gazebo＋Nav2 模擬與實車拍五紀錄」）；寫完自檢禁用字清單，不通過就改寫。
來源：Ch14 規則 3

### B146-61：提案或追蹤信以對方原話開頭、以下一步日期結尾

探索通話或面試後一天內送出的提案、感謝信、追蹤信，第一句引用對方描述擔憂的原話，最後一句寫具體下一步與日期。
**Why：** 原話證明你真的聽懂；沒有日期的下一步等於沒有下一步。
**How to apply：** 寫面試後追蹤信或 reply-writer 回覆獵頭時，從面試紀錄或對方訊息擷取一句原話放開頭、結尾寫回覆日期；遇到婉拒，建議記下「何時再聯絡」，不把一次「不」當結案。
來源：Ch14 規則 5

### B146-62：說不要早、一句理由、附替代方案

遇到超出能力或不該接的請求，第一時間用一句話說明落差，並立刻給一個較小的可行方案或轉介對象，不軟化成「也許」。
**Why：** 拖延的「也許」最後變成做不好的承諾，比早說不更傷信任。
**How to apply：** 面試被問到沒做過的（例：RAG、GCP 量產）時，用「我目前沒有實際做過 X；我做過的是 Y，可以在 Z 週內補上」句型；lhf 工廠判定某單位不適合自動化時，回報寫「不適合原因一句＋改由人做哪一段」。
來源：Ch16 規則 3

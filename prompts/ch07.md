# ch07｜Hermes 與 OpenClaw 當員工：客戶既有的代理能不能進組織圖，怎麼查

## 這章在講什麼

- adapter 是控制層（Paperclip：組織圖、目標鏈、預算、核准、紀錄）和 runtime（把模型變成員工的軟體）之間的橋；它讓客戶已經信任的代理去填角色。選 runtime 是角色定好之後的人事決定。
- 狀態標籤要像讀合約：Selectable 今天能選、Experimental 還在測、Coming soon 永遠不說成可用、Retired 已經沒了；每句話都附日期。OpenClaw gateway、Process、HTTP 三個「執行時可用但介面不能選」，兩件事都要講。
- 預算照有紀錄的花費執行；不回報成本的 runtime 等於沒有天花板，要靠供應商端限額並寫進 Blueprint。
- 內建 Hermes adapter 有條件：同機、Hermes 自己管模型、工具集要縮、原生 skill 唯讀且會自我改寫、成本要實測；用八項使用前檢查，不要停在「內建」那一項。
- OpenClaw 今天走四步邀請流程（邀請、貼提示、雇用核准與一次性金鑰、冒煙測試），不支援 skill sync，Paperclip 停機就暫停；全自動模式只關掉工具層提示，公司層規則照樣有效。單一代理有時才是誠實答案。

## 作者做過的實驗／例子

- 開場案例：用 Hermes 好幾個月的顧問公司老闆問「我的 Hermes 能坐進組織圖嗎」；顧問差點脫口說可以，想到客戶另一台機器上的 OpenClaw 而停下來，改用「查證流程＋日期」回答，客戶說這是第一次有廠商這樣回答相容性問題。
- 2026 年 10 月 20 日文件的 adapter 狀態表：Claude Code、Codex 為 Selectable（推薦），Hermes Agent 為 Selectable，native runner 為 Experimental，OpenClaw gateway、Process、HTTP 為 Coming soon，ACPX Local 與 Hermes Gateway 為 Retired。
- OpenClaw repo 當天約三十九萬顆星；第三方報導列出公開暴露的實例、有風險的社群 skill、prompt injection 為主要威脅，但發布者是競爭對手，要同樣懷疑。
- 單一代理試算：每月 8 個任務、每個省 30 分鐘、時薪 50 美元，毛價值 200；扣模型 30 與審查約 33，單一代理淨約 137；加上每月 3 小時、150 美元的公司層維護，變成約負 13。每月 40 個任務時毛價值 1,000，開銷只占一小部分。

## 教練解說要點

- 用一句話記 adapter：它把任務交給 runtime、把結果、用量和 session 交回控制層；回報那一半斷掉，控制層的預算與紀錄就瞎了。
- 標籤判斷可以寫成程式：凡不是 Selectable 的正面說法都算過度承諾，凡沒有日期的都算會過期的承諾。
- 成本回報的模擬要同時看「紀錄花費」和「實際花費」兩欄，差距就是上限擋不住的部分。
- 使用前檢查要跑完八項，第一個 FAIL 決定「可以」變成「要看情況」，其餘 FAIL 決定要補哪些控制。
- 損益兩平點由量決定，而且一定要把監督時間算進去；模型算出來的數字也要用程式驗算。

## 演練

> 說明：練習視窗工作目錄是 practice/。本書沒有附程式，Paperclip、Hermes、OpenClaw 都不安裝：用 Python 標準庫（不可 pip 安裝任何套件）寫小模擬，檔案放 practice/ch07/interactive/，用 `PYTHONUTF8=1 python ch07/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json（走 claude -p），整章最多呼叫 2 次。

### 練習 1：adapter、狀態標籤與成本回報

**目的**：重現「adapter 回報用量」與「看不見的花費擋不住」。
**送給練習視窗的提示詞**：

```text
寫 ch07/interactive/adapter_sim.py（只用標準庫，random.seed(146)，不可 input()，30 秒內跑完）：
1. 控制層有角色 Researcher、預算上限 50 美元；寫一個假的 runtime_hermes() 回傳 output、tokens、cost、session，adapter() 把結果寫成 run record 並累加花費；跑 3 次心跳，session 要延續。
2. 狀態標籤表（照本章 10 月 20 日的表），檢查 6 句業務說法：非 Selectable 的正面說法標「過度承諾」，沒附日期的標「沒寫日期」，統計幾句不能對客戶說。
3. 三個角色各跑 20 次、上限 50：Researcher 每次 3 美元有回報、Writer 每次 2.5 有回報、Poller（自寫腳本）每次 4 沒回報；印出紀錄花費、實際花費、在第幾次被擋；再加一列 Poller 搭配 40 美元供應商限額。
```

**觀察重點**：

- 6 句業務說法裡幾句不能講？連 Selectable 的那句也可能因為沒寫日期被標出來嗎？
- Poller 的紀錄花費和實際花費差多少？加了供應商限額後在第幾次停下？
- Researcher 在第幾次被 Paperclip 上限擋下，為什麼 Writer 剛好跑滿？

### 練習 2：Hermes 使用前檢查與 OpenClaw 邀請流程

**目的**：把本章兩個範本變成可以逐項跑的檢查與狀態機。
**送給練習視窗的提示詞**：

```text
寫 ch07/interactive/onboarding_check.py：
1. 八項 Hermes 使用前檢查，對客戶 A（全過）和客戶 B（Hermes 在另一台、模型不明、工具集沒縮、成本沒出現、原生 skill 沒審）各跑一次，印出每項 PASS／FAIL、第一個失敗項與全部失敗項。
2. OpenClaw 邀請流程狀態機：invited -> pending_approval -> approved_key_issued ->（pairing required 等待）-> paired -> active，逐一印出事件與狀態。
3. 把「OpenClaw 一次性金鑰」與「Hermes Agent」兩列追加到相依性登記表 ch07/interactive/dependency_register_add.csv（負責人、會壞什麼、檢查日、審核日、備案）。
4. 列出四個動作（讀資料夾、改草稿、對外寄信、刪除客戶檔案）在全自動模式下「工具層」與「公司層」各是什麼結果。
```

**觀察重點**：

- 客戶 B 的第一個失敗項是哪一項？它讓答案從「可以」變成什麼？
- 一次性金鑰是否被當成憑證寫進登記表？
- 全自動之下，哪兩個動作仍然要等人核准？

### 練習 3：讓真實模型當顧問，再用程式驗算

**目的**：看模型能不能給出「單一代理」的誠實答案，並用本章的假設驗算它的數字。
**送給練習視窗的提示詞**：

```text
寫 ch07/interactive/advice_check.py：
1. 用 practice/llm_agent.py 的 ask_json 呼叫 claude -p 一次：客戶是一人顧問公司、Hermes 裝在另一台筆電、每月 8 個任務、每個省 30 分鐘、時薪 50；附上 10 月 20 日的標籤（Hermes Selectable 需同機、OpenClaw gateway Coming soon）。
   請輸出 {"recommendation":"company|single_agent","reason","adapter_statement","monthly_numbers":{"gross","net_single","net_company"},"triggers":[...]}。
2. 用程式算每月 4、8、9、12、20、40 個任務時的毛價值、單一代理淨值（扣模型 30 與每任務 5 分鐘審查）、加公司層淨值（再扣 3 小時維護），找出加公司層不賠錢的門檻。
3. 檢查模型輸出：是否建議單一代理、adapter 說明有無日期、有無標籤、有無提到同機限制、有無過度承諾、有無重算觸發條件、數字與驗算是否差 10 美元以內。
4. 結果寫進 ch07/interactive/advice_report.md；呼叫失敗時改用內建範例。
```

**觀察重點**：

- 模型的建議和本章結論一致嗎？它的單一代理淨值有沒有把模型花費和審查時間算進去？
- 模型有沒有把「OpenClaw gateway」說成可以替 Hermes 跨機器連線？這種「把兩個標籤混在一起」的說法要不要算過度承諾？
- 加公司層不賠錢的門檻是每月幾個任務？為什麼「不賠」不等於「需要公司」？（每次模型輸出可能不同，照實記錄）
